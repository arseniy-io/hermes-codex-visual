# Остановка дерева и продолжение

Явная кнопка Stop вызывает `session.interrupt` с `cascade:true`. Обычный interrupt от редактирования/перенаправления сохраняет штатную область действия. `session.tree_status` читает подтверждение; `session.continue_tree(checkpoint_id)` запускает новый ход по сохранённой истории. Это не заморозка внешней команды на машинной инструкции.

Контроль выполняется там, где живёт настоящий агент, включая отдельный compute-host. Подтверждение stopped требует завершения принадлежащих задаче агентов, асинхронных помощников и фоновых процессов. Соседние чаты не затрагиваются. Checkpoint сохраняет историю и идентичность ребёнка; продолжение создаёт новое разрешённое выполнение и доставку результата родителю. Потерянное подтверждение не даёт автоматически повторить запуск.

`manifest.json` фиксирует каждый исходный и итоговый SHA-256. `core.patch` применяется только к известным исходникам; helpers перечислены отдельно. `scripts/stage-hermes-turn-control.py` создаёт кандидат, `scripts/install-hermes-turn-control.py --install` сверяет его, сохраняет откат и устанавливает. Несовместимое ядро не изменяется. Перед перезапуском рабочего шлюза необходимо подтвердить отсутствие активной работы штатным lifecycle guard.

Воспроизводимые проверки находятся в `verification/turn-control-core/`; оконный сценарий `turn-control` использует отдельный профиль и локальную модель. После обновления Hermes companion необходимо заново сверить с изменившимися исходниками.
